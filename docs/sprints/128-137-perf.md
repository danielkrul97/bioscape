> (GPU multi-spike benchmark + production wiring). 128 začíná novou perf

## Sprint 128 — bytemuck cast v `FieldGpu::download`

- **Cíl:** Eliminovat per-tick alokační overhead v field readbacku. Pre-S128
  cesta byla `bits.iter().map(|&b| f32::from_bits(b)).collect()` —
  iterátor přes každý u32, per-element `from_bits` reinterpret_cast,
  nový `Vec<f32>`. `bytemuck::cast_slice::<u8, f32>(&data).to_vec()` je
  bit-equivalent (stejný memory layout, jediný memcpy) s nulovým per-cell
  overheadem.

- **Výstup:**
  - `src/gpu.rs:1473` — replace map+collect with `bytemuck::cast_slice::<u8, f32>(&data).to_vec()`.
  - Behavioral: byte-identical (cast_slice == from_bits pro non-NaN, GPU
    field nikdy NaN neprodukuje — jen f32 s decay/diffusion stencil).
  - `cargo test --release --features gpu`: 176 passed, 1 ignored (parita
    `field_gpu_diffusion_matches_cpu` nedotčena, ε=1e-3 tolerance se
    nemění).

- **Poznámky:**
  - Win: ~256 KB / tick × 2 fields = 512 KB / tick alokační saved + per-element
    transformation eliminován. Reálné savings v rámci 0.99 + 0.82 ms field_ms je
    ~50–100 µs (alokace na 65k entries je rychlá). Předtěžiště pro S132.
  - `Maintain::Wait` zůstává — to dál řeší S132.

## Sprint 129 — drop GPU brownian dispatch

- **Cíl:** Eliminovat `brownian_gpu_rt_ms = 0.81 ms` (96 % `brownian_ms`).
  GPU brownian (xoshiro128++ per-cell) měla compute < 30 µs, ale
  upload_velocities + dispatch + `Maintain::Wait` + download_velocities
  = 0.8 ms čistý sync overhead. CPU `apply_brownian` (Box-Muller gaussian
  přes `cells.par_iter_mut`) běží sub-millisekund a žije ve stejném
  thread poolu.

- **Výstup:**
  - `src/main.rs:1138` — `apply_brownian_motion` zjednodušen na čistou CPU
    par_iter_mut path. GPU branch (upload + dispatch + readback + write-back)
    smazán; `BrownianGpu` zůstává v `GpuBrainState` Resource pro budoucí
    re-enable (`#[allow(dead_code)]`).
  - `THERMAL_NOISE` import odstraněn z main.rs (už nepoužit).
  - `DIAG_BROWNIAN_GPU_RT` registrace zachována, ale `add_measurement` se
    už nikdy nevolá → diag plot neukáže měření (graceful no-show).
  - `cargo test --release --features gpu`: 176 passed.

- **Poznámky:**
  - **Stochastic drift acceptable** per S113 konvence: rand::rng() Box-Muller
    vs xoshiro128++ produkují odlišné gaussian streamy, ale per-cell
    velocity perturbation amplituda je THERMAL_NOISE × √dt = identical
    distribution (just different sample). Pop-level metrics zůstávají
    v původním režimu.
  - Headless (separate binary) drží svou GPU brownian path — change je
    renderer-only.

## Sprint 130 — par_iter_mut sensor gather v `cells_brain_act`

- **Cíl:** Phase 1 sensor gather byla sériová — for-loop přes 1500 cells,
  každá hits `cell_grid.for_each_in_radius_toroidal` + `food_grid` radius
  query (4-pass spatial grid lookup). Pre-S130 měřeno ~6.5 ms / tick (= 15 ms
  total brain_act − 8.5 ms GPU rt = 6.5 ms CPU work). Cíl: rozprostřít
  na 12 vláken.

- **Výstup:**
  - `src/main.rs:1394` — pre-S130 `let gather = |...|` closure + sériový
    for-loop přepsán na single Bevy `Query::par_iter_mut().for_each(|...|)`
    block. Captures všechny &Sync (food_grid, cell_grid, smell, pheromone),
    lokální mutable state per per-cell closure body. `apply_shell_absorb`
    mutuje pouze self-cell. Post-gain inputs zapisuje do `cell.last_inputs`
    jako scratch (přepisuje se na konci brain_act stejně).
  - Sequential phase 2: HashMap build z `cell.last_inputs` přes `cells.iter()`.
    Read-only iteration ~1500× je rychlé.
  - `cargo test --release --features gpu`: 176 passed.

- **Poznámky:**
  - Bevy `QueryParIter` neimplementuje rayon `ParallelIterator` — nemá
    `.map().collect()`. Pattern `par_iter_mut().for_each` + scratch-write
    do existujícího per-cell pole (`last_inputs`) je idiomatický path.
  - Behavioral neutral: `id_to_inputs` HashMap má identický obsah
    (per-cell-id → post-gain inputs); pool_bonded_sensors ho čte by-key,
    iteration order není podstatný.

## Sprint 131 — par_iter_mut `apply_food_gravity`

- **Cíl:** Production diag ukázal 31k+ food entit (food_target s
  z_factor=50 přes `WORLD_HALF[2]=100`). `apply_food_gravity` iteroval
  všechny sériově — gravity math + transform.translation.z write +
  age_step + despawn check. Bulk cost je iterace, ne per-entity work.

- **Výstup:**
  - `src/main.rs:1163` — split na 2 pass: par_iter_mut na gravity + transform
    sync (31k entit / tick = paralelizovatelný hot loop), pak sériový
    age_step + despawn (Commands buffer není Sync; sequential pass jen
    čte position[2] do age_step + případný despawn).
  - `cargo test --release --features gpu`: 176 passed.

- **Poznámky:**
  - Food cap (z_factor scaling tweak) **nezvolen** — ovlivnil by biology
    (food density per-volume = ekologický parameter). par_iter_mut je
    behavior-neutral perf win.
  - Despawn check zůstává sériový — Bevy `Commands` v par_iter_mut.for_each
    by vyžadovala Mutex<Vec<Entity>> akumulaci, contention overhead by
    ROI snížil. Sériová iteration s `age_step` (tightly packed, cache-friendly)
    je dostatečně rychlá.

## Sprint 132 — opt-in GPU brain (default CPU SIMD path)

- **Cíl:** Eliminovat dominantní `brain_gpu_rt_ms = 8.5 ms` stall.
  Pre-S132 `cells_brain_act` GPU path: upload_inputs → forward_persistent
  → `download_hidden_outputs` (s `Maintain::Wait`) — 8.5 ms čistý CPU
  block na GPU completion. Per-S112 SIMD CPU brain forward batch_seq/1000
  = 635 µs, batch_seq/1500 ≈ 0.95 ms. Per-S117 SIMD CPU smell/pheromone
  step = 182 / 184 µs. **CPU SIMD path je 5–10× rychlejší než GPU + readback.**

- **Výstup:**
  - `src/main.rs:787` — GPU brain init guarded `BIOSCAPE_GPU_BRAIN=1` env
    var. Default off → `GpuBrainState` + `GpuFieldState` Resources se
    neinsertují → `Option<Res<...>>` checks v `cells_brain_act`,
    `cell_eats_food`, `update_smell_field`, `update_pheromone_field`,
    `cell_dies_on_zero_energy`, `cell_reproduces_on_threshold` všechny
    fallnou na CPU branch (CPU SIMD brain forward, CPU SIMD field step,
    CPU Hebbian, no-op brain weight upload/swap).
  - Opt-in zachován pro benchmark / regression — `BIOSCAPE_GPU_BRAIN=1
    cargo run --release` re-enabluje původní GPU path.
  - `cargo test --release --features gpu`: 176 passed (parita testy
    drží — kód paths se nezměnily, jen runtime selection).

- **Poznámky:**
  - **Behavioral drift expected**: GPU brain forward s f32 SIMD má jiný
    reduction order než CPU SIMD `wide::f32x8` path. Per S112 conventions
    drift na ULP úrovni je acceptable; pop-level metrics (cells, lineages,
    fov_avg, food) drží regime.
  - GPU smell/pheromone shader (S59) drží GPU residency mezi ticky; po
    S132 default je shader nečinný a CPU `SmellField::step` (S117 SIMD)
    je canonical. Bench `smell_field_step/populated` = 182.6 µs vs GPU
    rt ~0.5 ms = ~3× CPU win bez sync overhead.
  - Sprint 51 původní motivace ("GPU residency eliminuje 30 MB/tick brain
    upload") je obsolete: po S112 SIMD je CPU brain forward < 1 ms / tick;
    upload bottleneck z S44 už neexistuje (residency CPU storage = `Cell.genome.brain`).
    GPU path zůstává jako legacy artefakt + research benchmark fallback.
