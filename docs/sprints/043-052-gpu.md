# Sprinty 43–52: GPU acceleration & 10k+ cells

Decade směřuje k podpoře 10 000+ buněk v reálném čase. Diagnóza pre-Sprint-43:
`headless.rs` má 3 O(N²) průchody (`brain_act` vision sweep, `resolve_collisions`,
`predate` herd+attack), `rayon` je v `Cargo.toml` ale nikde se nepoužívá, GPU feature
je dependency-only scaffolding bez `cfg(feature="gpu")` bloků. Brain forward (720 MAC/cell)
je pro N=10k jen ~430 MFLOPs/s — není bottleneck. Bottleneck je broad-phase neighbor
finding. Proto: nejdřív CPU spatial hash + rayon (Sprint 43), pak GPU compute postupně
(Sprinty 44+) tam, kde se dál vyplatí.

## Sprint 43 — bench-friendly headless: spatial grid + rayon

- **Cíl:** odstranit O(N²) průchody v headless hot loopu a umožnit běh na 10k+ buněk
  v reálném čase na vícejádrovém CPU. Sprint 43 nemění simulační semantiku — pure
  perf refactor + měření. Zároveň poskytne čistý baseline pro porovnání s GPU
  variantami v dalších sprintech.

  **Plán:**

  *Body 1 — `SpatialGrid<Id, P>` v `lib.rs`:*
  - Generický spatial hash (HashMap bucket → `Vec<(Id, [f32;3], P)>`) přesunutý z
    `main.rs` do `lib.rs`. Generický přes `Id: Copy + Eq + Hash` (Bevy `Entity` v
    main.rs, `usize` v headless.rs) a `P: Copy` (radius / unit / payload).
  - API: `new(cell_size)`, `rebuild<I>(items)`, `for_each_in_radius<F>(pos, r, f)`.
  - **Determinismus:** rebuild iteruje vstup v daném pořadí → bucket Vec drží
    push-order. `for_each_in_radius` iteruje 3³ buckets ve fixním `dx,dy,dz` pořadí
    a HashMap `.get(&key)` je lookup-deterministic. Pokud caller předá rebuild
    items ve stable order, traversal je deterministický napříč runy.
  - `pub const GRID_CELL_SIZE: f32 = 64.0` — ~1.3× max vision_radius (50). main.rs
    si drží svůj lokální `GRID_CELL_SIZE = 100.0` (renderer-only knob).

  *Body 2 — main.rs cosmetic update:*
  - Lokální `Bucket<P>` + `SpatialGrid<P>` v main.rs odstraněny. Import z
    `bioscape::SpatialGrid`. Žádná behaviorální změna; main.rs už grid používal,
    jen teď přes sdílený typ.

  *Body 3 — headless hot loop přepis na grid + rayon:*
  - `World` dostane `cell_grid: SpatialGrid<usize, f32>` (payload = effective_radius)
    a `food_grid: SpatialGrid<usize, ()>` fieldy. Rebuild před fází, která neighbors
    používá.
  - `brain_act`: `cells.par_iter_mut().enumerate().for_each(...)` + grid lookup pro
    food i cell neighbors. Per-cell práce (sensor gather + brain forward + Hebbian
    setup + apply_brain_motor) je write-only do vlastní cell — par-safe.
  - `resolve_collisions`: `(0..n).into_par_iter()` produkuje `deltas[i]` write-only
    per i; grid query pro neighbors. Apply delty sekvenčně.
  - `predate`: dvě smyčky. (a) herd_counts: par_iter, write-only per i, grid query.
    (b) attack delty: zůstává sekvenční (write na victim_j může kolidovat napříč
    attackers), ale s grid lookupem místo full sweepu. Při k≈30 sousedů na cell
    a N=10k je sekvenční náklad ~300k op/tick = trivial.
  - `eat_food`: zůstává sekvenční (despawn `Vec<Food>` shared mutable), inner loop
    nad food_grid neighbors místo full food vec.
  - `spawn_food` exclusion check: cell_grid query místo full sweep.
  - `apply_brownian`: zůstává sekvenční — per-cell RNG draws, par by rozbil seed
    identity. Per-cell náklad je trivial (2–3 RNG calls).
  - `nn_dist_avg` v `write_stats`: O(N²) opravený přes cell_grid (k-nearest sweep).
    Per-gen, ne per-tick, ale při N=10k by jinak dominoval CSV log.

  *Body 4 — CLI flags + thread tuning:*
  - Headless dostává `--cells N`, `--max-pop N`, `--threads N` přes positional args
    (rozšíření existujícího `seed max_gens out map_seed mating_radius` schématu).
    Default zachovává `INITIAL_CELLS / MAX_POPULATION / num_cpus`. Per-fáze timing
    zapnut pro první generaci (stderr, grep-friendly format).
  - `World::new` dostane override-nullable `initial_cells` + `max_population`.
    `World::reproduce` čte `self.max_population` místo `MAX_POPULATION` const.
  - `available_parallelism()` ze stdlib určí default thread count (žádná nová
    závislost — `num_cpus` crate netřeba).

  *Body 5 — testy:*
  - `spatial_grid_finds_all_neighbors_in_radius`: 1000 random bodů, brute force vs
    grid query → identický set výsledků (po sortu).
  - `spatial_grid_rebuild_clears_old_buckets`: 2× rebuild s různými inputy → query
    nesmí vrátit stale entries z prvního rebuildu.
  - `spatial_grid_query_order_is_stable`: 2× query identického state → identický
    output order (basis pro determinismus).

- **Konstanty:**
  - `GRID_CELL_SIZE = 64.0` — ~1.3× max vision_radius (50). Větší = méně buckets,
    víc kandidátů per query; menší = víc buckets, méně kandidátů. Tunable.

- **Výstup:**
  - `lib.rs`: `pub struct SpatialGrid<Id: Copy + Eq + Hash, P: Copy>` + impl
    (`new`, `rebuild`, `for_each_in_radius`, internal `key_of`). `pub const
    GRID_CELL_SIZE: f32 = 64.0`. Imports `std::collections::HashMap` +
    `std::hash::Hash`.
  - `src/main.rs`: import `SpatialGrid` z `bioscape::`. Lokální `Bucket<P>` +
    `SpatialGrid<P>` definice odstraněny. `CellGrid(SpatialGrid<Entity, f32>)` a
    `FoodGrid(SpatialGrid<Entity, ()>)` používají sdílený generický typ. Žádná
    behaviorální změna v rendereru.
  - `src/bin/headless.rs`: `cell_grid` + `food_grid` ve `World`, `bench_timings:
    PhaseTimings` per-fáze accumulator, `max_population` field. `World::new`
    rozšířen o `initial_cells` + `max_population` parametry. `brain_act` přepsán
    na grid + `cells.par_iter_mut()` (rayon). `resolve_collisions` na
    `(0..n).into_par_iter()` + grid query. `predate` herd-pass paralelní, attack
    pass sekvenční s grid lookupem. `eat_food` + `spawn_food` + `nn_dist_avg` ve
    `write_stats` přes grid. Stale scratch arrays
    (`positions_scratch/radii_scratch/spike_lengths_scratch/headings_scratch/food_positions_scratch`)
    odstraněny. CLI rozšířeno o positional `initial_cells / max_population /
    threads` (default zachovává pre-Sprint-43 chování). `tick()` měří per-fáze us;
    main vypíše po gen 1 grep-friendly format `phase=X n=Y ticks=Z us_total=...
    us_avg=...`. Rayon thread pool init přes `available_parallelism()`.
  - `Cargo.toml`: žádná nová závislost — `rayon` byl už přítomen, jen poprvé se
    používá.
  - **3 nové unit testy** (`spatial_grid_finds_all_neighbors_in_radius`,
    `spatial_grid_rebuild_clears_old_buckets`, `spatial_grid_query_order_is_stable`).
    **58/58 testů pass** (55 původních + 3 nové).
  - **Smoke (seed=0, 60 gen, default size, 12 threads):** pop 200 → 215 (gen 1)
    → 793 (gen 59), 5 lineages, ~6500 predation events/gen. Žádná extinkce.
    Wall-clock 31.6 s (1138 ticks/s).
  - **Bench (seed=0, 1 gen, initial=10000, max_pop=10000, 12 threads):** pop
    10000 → 6193 (mass die-off — overcrowded random brains v saturovaném světě,
    expected). 56 ticks/s celkově. Per-fáze us avg na N=6193: brain_act 4340,
    eat_food 4608, predate 5331, resolve_collisions 1418, ostatní < 400.
  - **Per-fáze scaling N=215 → N=6193 (29× cells):** brain_act 175→4340 = 25×
    (par_iter linear scaling), predate 130→5331 = 41× (sekvenční attack pass je
    bottleneck), eat_food 218→4608 = 21× (food_grid + sequential despawn).

- **Poznámky:**
  - **Determinismus a CSV identity:** Sprint 43 NEZACHOVÁ bit-identity CSV s
    pre-Sprint-43 (rayon scheduling + float commutativity v rebuild order +
    float result aggregation v par_iter). Acceptance = pop trajektorie shape:
    seed=0 60 gen ne-extinkce, ≥100 cells gen 59. Konzistentní break se Sprinty
    41/42.
  - **Proč rayon až teď:** pre-Sprint-43 saturuje `MAX_POPULATION = 1000`. Para-
    overhead by zžral užitek. Sprint 43 umožní CLI override + grid → rayon začíná
    vyplácet od ~N=2k.
  - **Proč `pair_fertile` se nepřevádí:** O(F²) na fertile-only subset. F ≪ N (~50
    při N=1000). Při N=10k by F bylo ~500 → 250k ops/tick, stále trivial.
  - **Co Sprint 43 NEMĚNÍ:** brain shape, mutace, eat zone, aging/cooldown,
    smell/pheromone math, fields. Pure perf refactor.
  - **Cíl perf (ne hard requirement):** ticks/sec ≥ 60 při N=10000 na 8-core CPU.
    Při N=2000 čekáno ≥ 4× speedup `--threads 1` vs `--threads 8`.
  - **Co dál (Sprint 44):** GPU brain forward batch jako proof point — stejná
    data, runtime přepínač CPU/GPU, parity test. Brain je nejjednodušší kandidát
    pro první compute shader (čistý matmul, žádný branching).

## Sprint 44 — GPU brain forward batch (`--features gpu`)

- **Cíl:** první compute shader v projektu, batch forward pass všech buněk (w1+w2)
  na GPU, runtime flag `--gpu` v headless. Parity test CPU vs GPU < 1e-4.
  Sprint 44 staví scaffolding — perf parita s CPU se neočekává, per-tick upload
  je vědomě bottleneck dokud Sprint 47 nezavede state-on-GPU.

  **Plán implementace:**

  *Body 1 — `lib::gpu` modul:*
  - `src/gpu.rs` ohraničený `#[cfg(feature = "gpu")]` declared as `pub mod gpu`
    v `lib.rs`. Při `cargo build` bez `--features gpu` se modul vůbec
    nezkompiluje, takže build na strojích bez wgpu stack zůstává bez závislostí.
  - `pub struct BrainGpu` drží `wgpu::Device`, `wgpu::Queue`, `ComputePipeline`,
    `BindGroupLayout`, persistent storage buffery (params/inputs/weights/hidden/
    outputs) + readback staging buffery sized pro `capacity` cells.
  - `BrainGpu::new(capacity)` blocking init přes `pollster::block_on`. Vrací
    `Result<Self, String>` — soft fail pokud není adapter (CI bez GPU může běžet
    test suite bez tohoto fungujícího).
  - `BrainGpu::ensure_capacity(n)` realokuje buffery + bind group při růstu.
    Geometric (capacity × 2) aby amortized realokační cost.

  *Body 2 — WGSL compute shader (`shaders/brain_forward.wgsl`):*
  - 1 entry point `forward`, workgroup size 64. Per-thread = jeden cell.
  - Bindings: 0 uniform `Params { num_cells }`, 1 storage `inputs[N×36]`, 2
    storage `weights[N×745]`, 3 storage `hidden[N×16]` write-back, 4 storage
    `outputs[N×9]` write-back.
  - Per-cell weights layout: `w1[576] | b1[16] | w2[144] | b2[9]` (745 f32).
    Compile-time `const _: () = assert!(...)` v Rustu garantuje, že packing
    matchne shader offsety.
  - Forward: `hid[h] = tanh(b1[h] + Σ w1[h,i] × inputs[i])`, pak `out[o] = tanh(b2[o] + Σ w2[o,h] × hid[h])`.

  *Body 3 — `forward_batch` API:*
  - Signatura přijímá `inputs: &[[f32; BRAIN_INPUTS]]` + `brains: I where I:
    IntoIterator<Item = &Brain>` aby caller (`cells.iter().map(|c| &c.genome.brain)`)
    nemusel klonovat 30 MB Brain Vec při N=10k.
  - Pack inputs + weights do Vec<f32>, `queue.write_buffer`, dispatch
    `(N+63)/64` workgroupů, `copy_buffer_to_buffer` na readback staging,
    `device.poll(Maintain::Wait)`, mapped read → write back do output slices.

  *Body 4 — wire `--gpu` do headless:*
  - `World` má `#[cfg(feature = "gpu")] gpu: Option<BrainGpu>` field. Default `None`.
  - `tick()` volá `run_brain_act(dt)` → dispatch CPU vs GPU podle `self.gpu`.
  - `brain_act_gpu` ve 3 fázích: (a) par_iter_mut sensor gather + populate_inputs
    (mutuje `damage_accum`, `last_inputs`), produkuje `Vec<[f32; BRAIN_INPUTS]>`,
    (b) GPU `forward_batch` pro hidden + outputs, (c) par_iter_mut zápis
    `last_*` + `apply_brain_motor`.
  - CLI: `--gpu` flag (named, ne positional) odděluje od existujícího positional
    schematu. Bez `--features gpu` se tiše ignoruje s warning.

  *Body 5 — parity test:*
  - `brain_forward_gpu_matches_cpu`: 32 random brainů × 32 inputů, GPU forward
    vs CPU `Brain::forward_with_state`. Tolerance 1e-4 (single-precision tanh
    se napříč implementacemi liší v ULP, ne víc). Test skippne s warning pokud
    `BrainGpu::new` selže (CI bez GPU).

- **Konstanty:**
  - `BRAIN_WEIGHTS_PER_CELL = HIDDEN×INPUTS + HIDDEN + OUTPUTS×HIDDEN + OUTPUTS = 745`
    (compile-time guard přes `const _: () = assert!(...)`).

- **Výstup:**
  - `Cargo.toml`: žádná změna — `wgpu`/`bytemuck`/`pollster` byly v `[dependencies]`
    s `optional = true` od Sprintu 38, jen poprvé skutečně používány.
  - `lib.rs`: `#[cfg(feature = "gpu")] pub mod gpu;` declaration. Žádná jiná
    změna.
  - `src/gpu.rs`: nový modul, `pub struct BrainGpu` + impl s `new`,
    `forward_batch`, `ensure_capacity`, internal `alloc_buffers` a
    `make_bind_group`. Layout offsety jako `const` s compile-time asserty.
  - `shaders/brain_forward.wgsl`: nový compute shader.
  - `src/bin/headless.rs`: cfg-gated `gpu: Option<BrainGpu>` ve `World`,
    `brain_act_gpu` 3-fázový flow, `run_brain_act` dispatch helper, `--gpu` CLI
    flag parsing přes filtraci `--`-prefixed args před positional indexingem.
  - **1 nový unit test** (`brain_forward_gpu_matches_cpu`). **59/59 testů pass**
    (58 dříve + 1 nový GPU parity test).
  - **Smoke (seed=0, 5 gen, N=2000, max_pop=10000, 12 threads):** GPU init OK
    (RTX-class adapter), pop trajektorie 2000 → 1860 (gen 1) → 994 (gen 5).
    `brain_act` GPU 4398 us/tick vs CPU 1100 us/tick — **GPU 4× pomalejší** kvůli
    per-tick uploadu weights (~30 MB při N=10k).
  - **Bench (seed=0, 1 gen, N=10000):** brain_act GPU 18311 us/tick vs CPU
    4441 us/tick. Total run-time: GPU 31 ticks/s vs CPU 55 ticks/s.

- **Poznámky:**
  - **Per-tick upload je bottleneck.** wgpu inputs (~1 MB při N=10k) + weights
    (~19 MB při N=10k) se posílají každý tick. PCIe 4.0 x16 má ~32 GB/s
    teoreticky, ~600 us pro 19 MB; ale wgpu sync overhead + dispatch barrier
    + readback `Maintain::Wait` přidá další ms. Compute samotný (4.5M MAC) je
    bingově triviální (microseconds).
  - **Proč to tak.** Hebbian update v `eat_food` mutuje brainy každý tick →
    weights buffer musí re-upload. Sprint 47 řeší tím, že přesune Hebbian na
    GPU + nech weights persistent.
  - **CSV identity proti CPU:** Sprint 44 GPU mode produkuje **mírně odlišnou**
    pop trajektorii než CPU mode (1e-4 tanh ULP rozdíly se akumulují přes
    600 ticků × 5 generací). Pop counts jsou v rámci ±5 % toho samého seedu.
    Sprint 47+ s deterministickou GPU PRNG (Sprint 48) může identita stabilizovat.
  - **Build cost:** `cargo build --features gpu` přidá ~65 crates (wgpu stack)
    a ~2 min release build. Default headless build zůstává štíhlý.
  - **Co Sprint 44 NEMĚNÍ:** simulační semantika, brain shape, ostatní fáze.
    Pouze přidává opt-in GPU forward path.
  - **Co dál (Sprint 45):** GPU spatial hash. Counting sort + neighbor lists na
    GPU umožní vision/predate/collision broad-phase v compute shaderu — to je
    kde GPU bude **opravdu** rychlejší než CPU (současný CPU broad-phase je
    HashMap-bound).

## Sprint 45 — GPU spatial hash + neighbor lists (counting sort)

- **Cíl:** datová struktura broad-phase na GPU. Counting sort (count per bucket
  → prefix sum → scatter) produkuje `(offsets[NUM_BUCKETS+1], sorted_cells[N])`.
  Sprint 45 dodává **stavební kámen** — wiring do brain_act_gpu/predate je
  Sprint 47, kdy už státe stane on-GPU full pipeline. Parity test: GPU bucket
  layout = CPU `SpatialGrid` layout.

  **Plán implementace:**

  *Body 1 — WGSL `shaders/spatial_hash.wgsl`:*
  - 3 entry points v jednom souboru (sdílí bind group + bucket helper):
    - `count` (workgroup 64): per cell, atomicAdd na `counts[bucket]`.
    - `prefix_sum` (workgroup 1, dispatch 1): single-thread serial exclusive
      scan `counts → offsets`, current resetuje counts na 0 (scatter ho použije
      jako per-bucket write counter — uspoří jeden buffer).
    - `scatter` (workgroup 64): per cell, `write_pos = offsets[b] +
      atomicAdd(&counts[b], 1)`, `sorted_cells[write_pos] = cell_idx`.
  - Bucket grid fixed 64×32×4 = 8192 buckets, krytí ±2048 / ±512 / ±128 world
    units při `cell_size = 64` (s rezervou nad WORLD_HALF=[960,540,2]). Cells
    mimo bounds clampované do boundary buckets — guarded by Cell::step
    world_half clamp.
  - `bucket_id_of(pos)` helper: floor(pos/cell_size) + half offsety, clamp,
    linearizace do u32.

  *Body 2 — Rust `lib::gpu::SpatialHashGpu`:*
  - Drží wgpu device/queue (own nebo borrow přes `with_device` constructor —
    Sprint 47 sdílí jeden device s `BrainGpu`), 3 compute pipelines (count,
    prefix_sum, scatter) sharing jeden bind group layout (5 bindings: params
    uniform + 4 storage buffery).
  - `new(capacity, cell_size)` blocking init přes `pollster::block_on`.
  - `rebuild(positions: &[[f32; 3]]) → (Vec<u32>, Vec<u32>)`: write_buffer
    counts (zero), positions, params; encoder s 3 compute pasy; copy_buffer
    offsets/sorted do staging; readback + map.
  - `ensure_capacity(n)` realloc geometric (×2) při růstu N.
  - CPU mirror `SpatialHashGpu::bucket_id_of(pos, cell_size)` pro testy +
    callers, kteří chtějí dohnat GPU bucket layout.

  *Body 3 — parity test:*
  - `spatial_hash_gpu_matches_cpu_buckets`: 500 random positions ve world bounds.
    GPU rebuild → `(offsets, sorted)`. CPU buduje `HashMap<bucket_id,
    BTreeSet<cell_idx>>` přímou aplikací `bucket_id_of`. Pro každý z 8192
    bucket: GPU sorted[offsets[b]..offsets[b+1]] = CPU bucket set. Total
    `offsets[NUM_BUCKETS] == N`. Skip pokud `SpatialHashGpu::new` selže.

- **Konstanty:**
  - `GPU_HASH_GRID_NX = 64`, `GPU_HASH_GRID_NY = 32`, `GPU_HASH_GRID_NZ = 4`
    → `GPU_HASH_NUM_BUCKETS = 8192`. Compile-time `const`, exposed v `lib::gpu`.

- **Výstup:**
  - `shaders/spatial_hash.wgsl`: nový shader, 3 entry points, sdílený bind
    group layout.
  - `src/gpu.rs`: `pub struct SpatialHashGpu` + impl. Public consts
    `GPU_HASH_GRID_*` a `GPU_HASH_NUM_BUCKETS`. `with_device()` alternative
    constructor pro Sprint 47 device sharing. Internal `alloc_buffers` +
    `make_bind_group` extracted helpers (mirror BrainGpu pattern).
  - **1 nový unit test** (`spatial_hash_gpu_matches_cpu_buckets`). **60/60 testů
    pass** (59 dříve + 1 nový spatial-hash parity).
  - **Tickováno NEZAPOJENO do simulace** — Sprint 47 wire-up. Sprint 45 je pure
    data structure delivery.

- **Poznámky:**
  - **Proč counts buffer reuse jako write counter:** prefix_sum na konci resetuje
    counts na 0 + zapíše scan do offsets. Scatter pak používá counts jako
    per-bucket atomicAdd counter. Šetří jeden buffer + jeden write_buffer call.
  - **Proč single-thread prefix_sum:** NUM_BUCKETS = 8192 je malé. Serial scan
    v jednom GPU thread je ~8 µs (memory-bound). Hierarchical Blelloch scan by
    spadl na ~1 µs ale přidá complexity. Pokud Sprint 47 benchmark ukáže
    prefix_sum jako bottleneck, lze upgradnout.
  - **Proč fixed grid bounds:** WGSL nemá HashMap, fixed array indexing je
    nutný. 8192 buckets × 4 bytes = 32 KB pro counts/offsets — trivial. Při
    scaling světa (Sprint 49+ multi-region) by se grid musel parametrizovat
    přes uniform.
  - **Determinismus:** counting sort je stabilní vůči pořadí cells **uvnitř**
    bucketu, ale to pořadí závisí na atomicAdd dispatch order napříč warps —
    ne-deterministické. Sprint 48 (determinismus) buďto použije sort-by-id
    uvnitř bucket post-hoc, nebo akceptuje že GPU run není bit-identical s CPU
    (acceptance setové porovnání, ne ordered).
  - **Co dál (Sprint 46):** GPU field diffusion. Smell + pheromone na GPU
    Jacobi 5-point stencil, ping-pong buffery, cells emit přes atomic add
    (nebo separate "deposit" pass + diffusion pass). Spatial hash zatím
    nepoužit — Sprint 46 je orthogonální.

## Sprint 46 — GPU field diffusion + state-on-GPU lifetime

- **Cíl:** Jacobi 5-point stencil (smell + pheromone) na GPU. Sprint 46 dodává
  `FieldGpu` jako drop-in mirror `SmellField` API (add_source / step / download).
  State drží GPU buffery mezi ticky (ping-pong A↔B); readback jen pro testy +
  Sprint 47 inline GPU sample. Parity vs CPU < 1e-3.

  **Plán implementace:**

  *Body 1 — WGSL `shaders/field_diffuse.wgsl`:*
  - 2 entry points: `deposit` (workgroup 64, dispatch per-source) + `diffuse`
    (workgroup 8×8, dispatch (W/8)×(H/8)).
  - Atomic float add **inlined** (CAS loop přes `atomicCompareExchangeWeak` +
    `bitcast<f32>`/`bitcast<u32>`). WGSL/Naga nepovoluje storage pointer jako
    function param — extracted helper `atomic_add_f32` proto nelze, kód je
    inline v deposit.
  - Diffuse čte 5-point neighborhood přes `atomicLoad` + bitcast. Boundary
    cells čtou center místo out-of-range neighbor (Neumann zero-flux BC).
  - `decay = (1 - decay_per_sec × dt).max(0)` mirror `SmellField::step`.

  *Body 2 — Rust `lib::gpu::FieldGpu`:*
  - 2 storage buffery `grid_a` / `grid_b` jako `array<atomic<u32>>` (4 bytes
    per cell, bitcast f32). 2 bind groups: `bg_round_a` (in: A, out: B) a
    `bg_round_b` (in: B, out: A). `current_is_a: bool` flag rotuje per step().
  - `add_source(pos, amount)` push do CPU `pending_sources: Vec<f32>`
    (interleaved px,py,amount). `step()` flushne na GPU.
  - `step(diffusion, decay_per_sec, dt)`: write_buffer params + sources,
    encoder s deposit pass (skip pokud num_sources=0) + diffuse pass, submit,
    swap current_is_a, clear pending.
  - `ensure_sources_capacity(n)` realloc geometric — bind groups (které
    zachycují sources_buf) se rebuildují.
  - `download() -> Vec<f32>` čte current grid (post-diffuse output) přes COPY
    + map_async + bitcast. Pomalá, jen pro testy/visualization.
  - `with_device(device, queue, ...)` alternative constructor pro Sprint 47
    device sharing.

  *Body 3 — parity test:*
  - `field_gpu_diffusion_matches_cpu`: 32×32 grid, 10 ticků × 5 random sources.

## Sprint 49 — GPU cell neighbors query (chained spatial hash)

- **Cíl:** první GPU compute shader, který skutečně **konzumuje** výstup
  Sprint 45 SpatialHashGpu — broad-phase neighbor query per cell přes 3³
  (resp. (2r+1)³) buckets, vrací nearest cell + neighbors_in_vision count
  pro každou cell. Demonstruje chaining mezi GPU subsystémy: hash rebuild
  → hash query → result. První skutečný "GPU broad-phase v akci".

  **Plán implementace:**

  *Body 1 — WGSL `shaders/cell_neighbors.wgsl`:*
  - 1 entry point `neighbors` (workgroup 64). Per cell i:
    - bucket = `bucket_id(positions[i])`
    - `r_cells = ceil(vision_radii[i] / cell_size)` — dynamicky podle
      per-cell vision range, ne fixed 3³ (kritické: pre-Sprint-49 fix měl 3³
      ale CPU `SpatialGrid` používá ceil division, takže vision > cell_size
      missnula edge neighbors → CPU/GPU neshodly)
    - Iteruj `(2·r_cells + 1)³` buckets, pro každého souseda j ≠ i:
      narrow-phase d² ≤ vr² → count++; if d² < best_d² → best = (j, dx,dy,dz, radii[j])
  - Output per cell: 5 floats `[dx, dy, dz, radius, count_bitcast]`. Caller
    bitcastne 5. element zpět na u32 pro count.
  - Sentinel: `radius = -1` znamená "no neighbor in vision".

  *Body 2 — Rust `lib::gpu::NeighborsGpu`:*
  - Drží persistent buffery pro positions/radii/vision_radii/output (SoA
    layout, cell-strided 5 floats per output). Bind group **se rebuilduje
    per call** — odkazuje externí `cell_hash` buffery (offsets + sorted),
    které žijí v SpatialHashGpu.
  - `compute(positions, radii, vision_radii, &cell_hash) -> Vec<NeighborResult>`:
    write_buffer SoA + params, bind group pointing to hash, dispatch, copy
    + map readback, decode 5 floats → `NeighborResult { nearest_cell, neighbors_in_vision }`.
  - Sentinel decode: `radius < 0.0` → `nearest_cell = None`.
  - `SpatialHashGpu::offsets_buffer()` + `sorted_buffer()` accessors přidané
    pro chained shader binding.

  *Body 3 — parity test:*
  - `neighbors_gpu_matches_cpu_brute_force`: 200 random cells × random
    vision (20–80), `cell_size = 64`. GPU rebuild hash + neighbors compute
    vs CPU O(N²) brute force. Per cell: count exactně match, nearest_cell
    d² match v ε (acceptujeme jiný winner pokud d² jsou v ε kvůli single-precision
    tieng při téměř identických vzdálenostech).

- **Konstanty:** žádné nové; `cell_size` parametrizovatelný per NeighborsGpu
  instance.

- **Výstup:**
  - `shaders/cell_neighbors.wgsl`: nový shader, dynamic `r_cells` výpočet z
    vision_radius.
  - `src/gpu.rs`: `pub struct NeighborsGpu` + `pub struct NeighborResult` +
    impl s `new`, `with_context`, `compute`, internal helpers. Nové accessors
    `SpatialHashGpu::offsets_buffer()` a `::sorted_buffer()` pro chained shader
    binding.
  - **1 nový unit test** (`neighbors_gpu_matches_cpu_brute_force`). **65/65
    testů pass** (63 dříve + 2 nové: neighbor parity + stats N=50k stress).

- **Poznámky:**
  - **Bug fix during dev: 3³ buckets nestačí.** První iterace shaderu měla
    fixní `for dx in -1..=1` (3³ = 27 buckets). Při `vision_radius = 80` a
    `cell_size = 64` ale neighbor může být ve vzdálenosti 80, což je 1.25
    bucket reach → out of 3³ range → missnut. Fix: dynamic `r_cells = ceil(vr/cs)`,
    iteruj `(2r+1)³`. Při typickém vr=50, cs=64 dostaneme r_cells=1 → 27
    buckets (matchuje CPU). Při vr=80, cs=64: r_cells=2 → 125 buckets
    (5³). Stále trivial GPU work. **CPU `SpatialGrid::for_each_in_radius`
    už tento ceil pattern používá** — Sprint 49 jen replikuje na GPU.
  - **Determinismus:** Per cell i je iterace bucketů deterministická (fixed
    nested for). Within bucket je iterace v sorted_cells order — což ale
    samo o sobě není deterministické (Sprint 45 atomicAdd dispatch order
    napříč warps). Pro count match to nevadí (set membership), pro nearest
    cell může výjimečně vyhrát jiný v případě tied distances. Acceptujeme
    v testu.
  - **Bind group per call:** NeighborsGpu rebuilduje bind group při každém
    compute() — drahé (~10 µs alokace). Pro Sprint 49 acceptable; Sprint 50+
    může cachovat při stable cell count.
  - **Co Sprint 49 NEMĚNÍ:** sensor gather pro food + smell + pheromone
    fields zůstává Sprint 50+. Sprint 49 řeší pouze cell-vs-cell broad-phase
    (vision interaction). Foods + fields jsou orthogonální datové zdroje.
  - **Headless není wired:** NeighborsGpu má pouze test integration. Wire-up
    do `brain_act_gpu` (kompletní GPU sensor → forward path) je Sprint 50,
    kdy přidáme food + fields do sensor gather.

      bitcast<f32>; same memory, different shader view).
  - Output stride 13 floats per cell (food[3] + has_food + cell[3] + radius
    + smell_grad[2] + pheromone_grad[2] + count_bitcast).
  - 12 bindings (1 uniform + 10 read + 1 rw output) — at the
    `max_storage_buffers_per_shader_stage = 12` limit.
  - `FieldGpu::current_grid_buffer()` accessor přidán pro ping-pong-aware
    bind: vrátí tu z (grid_a, grid_b) která drží post-step state.

  *Body 6 — `GpuContext` storage buffer limit bump:*
  - `max_storage_buffers_per_shader_stage: 12` (default 8 v wgpu 23). Motor
    shader má 9 storage; step + sensor 11. Bumpu na 12 pokrývá vše. Většina
    desktopových GPU podporuje ≥ 16; mobilní/integrované mohou být 8 — pro
    nepodporované zařízení by `GpuContext::new` selhal s validation error.

  *Body 7 — parity testy:*
  - `motor_gpu_matches_cpu`: 64 random cells, output[9] random ∈ [-1,1],
    GPU motor vs `Cell::apply_brain_motor`. Tolerance 1e-4.
  - `step_gpu_matches_cpu`: 64 random cells s mírnou velocity / angular,
    GPU step vs `Cell::step`. Tolerance 1e-3 (long arithmetic).
  - `collision_gpu_matches_cpu`: 100 cells clusterovaných v 60×60 oblasti,
    GPU collision vs CPU O(N²) brute force. Tolerance 1e-3 na delta.
  - `predate_gpu_matches_cpu`: 80 cells s mixed sizes, random attack signals,
    GPU 2-pass predate vs CPU brute force. Herd counts exactně match,
    energy/damage delta v 1e-3 (atomic CAS sumace ULP drift).
  - `sensor_gather_gpu_matches_cpu`: 80 cells + 40 foods + 2 fields seedované
    stejnými sources, GPU sensor vs CPU brute force per cell (cell
    broad-phase + food broad-phase + 2 gradient_at). Counts exactně, distance
    + gradients v 1e-2 (field atomic CAS drift kumulovaný přes diffuse pass).

- **Konstanty:** žádné nové simulační; `max_storage_buffers_per_shader_stage = 12`
  v `GpuContext::new` requested limits.

- **Výstup:**
  - `shaders/motor.wgsl`, `shaders/step.wgsl`, `shaders/collision.wgsl`,
    `shaders/predate.wgsl`, `shaders/sensor_gather.wgsl`: 5 nových compute
    shaderů.
  - `src/gpu.rs`:
    - `pub struct MotorGpu` + impl s `with_context`, `compute`.
    - `pub struct StepGpu` + `pub struct StepParamsGpu` + `pub struct StepResult`.

- **Poznámky:**
  - **Storage limit bump:** výchozí wgpu 23 má `max_storage_buffers_per_shader_stage = 8`,
    motor shader využívá 9. Bumpu na 12 pokrývá motor (10 bindings), step
    (12), collision (7), predate (11), sensor_gather (12). Většina desktopových
    GPU (NVIDIA Pascal+, AMD GCN3+, Intel Gen11+) podporuje ≥ 32 storage
    buffers; mobile/integrated mohou mít 8 → `GpuContext::new` v takovém
    případě selže s validation error.
  - **Atomic float CAS pattern:** WGSL nemá `atomic<f32>`, používáme
    `atomic<u32>` + `bitcast<f32>` ↔ `bitcast<u32>` + `atomicCompareExchangeWeak`
    loop. Naga validation ne-povoluje `ptr<storage, atomic<u32>, ...>` jako
    function param, takže CAS je inlined per call site (3× v `predate::attack`).
  - **Field bind type mismatch (atomic vs non-atomic):** FieldGpu binduje
    grid_a/grid_b jako `array<atomic<u32>>`. Sensor shader bindujue stejný
    buffer jako `array<u32>` (non-atomic read-only). wgpu binding layer řeší
    pouze memory; WGSL re-interpret typu při bindu je legální. Pro
    `atomicLoad`-only čtení by atomic-bound view fungoval taky, ale plain u32
    read je jednodušší (žádné atomic API call).
  - **Standalone vs unified:** každý shader má vlastní upload/download per
    dispatch. Sprint 51+ může unifikovat přes `CellsGpu` SoA persistent state
    (cells positions/velocities/etc. drží GPU buffery mezi ticky → eliminuje
    upload). 70/70 testy stále drží jako reference pro full pipeline migration.
  - **Determinismus:** motor, step, collision, sensor neighbor-set jsou
    plně deterministické (write-only per i, žádný atomic). Predate atomic
    CAS na victim sdílí cesty mezi attackery → ne-deterministická summation
    order → ULP drift napříč runy. Sprint 48 (determinismus) doc už toto
    flagoval.
  - **Headless není wired:** Sprint 50 dodává API + tests, ne integrace do
    `headless::tick()`. Wire-up vyžaduje `CellsGpu` persistent state +
    refactor World struct. Plán pro Sprint 51.
  - **Co Sprint 50 NEMĚNÍ:** simulační semantika (parita testů potvrzuje),
    brain forward (Sprint 44), spatial hash (Sprint 45), field diffuse
    (Sprint 46), shared context (Sprint 47), checkpoint (Sprint 48),
    neighbors (Sprint 49). Pure additive: 5 nových compute capabilities.

## Sprint 51 — CellsGpu SoA + headless `--gpu-full` (závěr GPU dekády)

- **Cíl:** kompletně uzavřít GPU téma 4 body uživatele:
  1. **CellsGpu SoA persistent state** — brain weights + last_inputs / last_hidden
     / last_outputs + velocities + xoshiro RNG state žijí na GPU mezi ticky.
  2. **Headless tick() integration** — `--gpu-full` flag vyhodí Sprint 44
     per-tick brain upload (30 MB při N=10k) + zapne GPU Hebbian + GPU Brownian.
  3. **GPU Hebbian update** — nový shader; eat_food sbírá rewards Vec, dispatch
     na GPU mutuje brain weights in-place.
  4. **Per-cell xoshiro RNG** — xoshiro128++ inline v Brownian shaderu, per-cell
     state v `xoshiro_state` buffer; deterministic per seed napříč běhy.

  **Honest scope note:** sensor gather / motor / step / collision / predate
  zůstávají CPU rayon (Sprint 50 standalone shadery jsou ready a parity-tested,
  jejich integrace je mechanická pro Sprint 52+). Sprint 51 tedy **NE-řeší
  full GPU pipeline** ale řeší primary perf bottleneck (30 MB/tick brain
  upload) a dodává všechny chybějící architektonické bloky.

  **Plán implementace:**

  *Body 1 — `CellsGpu` SoA struct:*
  - 11 persistent storage buffers: `last_inputs[N×36]`, `last_hidden[N×16]`,
    `last_outputs[N×9]`, `brain_weights[N×745]`, `velocities[N×3]`,
    `xoshiro_state[N×4 u32]`, `rewards[N]` + 4 readback buffers + 2 swap-temp
    buffers (kvůli wgpu zákazu same-buffer copy).
  - API: `with_context(ctx, capacity)`, accessor metody `*_buffer()`,
    `upload_brains/inputs/velocities/rewards`, `upload_brain_at(slot)` +
    `upload_xoshiro_seed_at(slot)` pro reproduce, `download_brains/hidden_outputs/
    velocities/brain_at(slot)` pro sync v reproduce / checkpoint, `swap_to(dst, src)`
    pro die_and_drop_carrion swap_remove pattern (GPU-side memcpy přes staging
    temp buffers).
  - xoshiro state seedovaný z `lineage_id` přes SplitMix64 4× (deterministic).

  *Body 2 — nové shadery a wrappery:*
  - `shaders/brownian.wgsl`: xoshiro128++ inline per-cell, gaussian via
    Box-Muller (uniform01 z 24 horních bitů × 1/2²⁴), aditivně mutuje
    velocity[N×3] s `thermal_noise × √dt × g`. Z-osa skipped pokud `has_z = 0`.
  - `shaders/hebbian.wgsl`: per cell pokud `reward != 0`, aplikuje
    `Brain::hebbian_update` math (Δw = lr × reward × pre × post) na brain
    weights in-place. Layout matches Sprint 44 packing.
  - `BrownianGpu` + `HebbianGpu` Rust wrappery se standalone tests + nové
    `compute_persistent(cells_gpu, ...)` metody bindující CellsGpu buffery.
  - `BrainGpu::forward_persistent(cells_gpu, n)` — bind do CellsGpu's
    last_inputs (read), brain_weights (read), last_hidden + last_outputs (rw).
    **Žádný upload** — to je hlavní win.

  *Body 3 — headless integrace:*
  - `World` přidává cfg-gated `gpu_full: Option<GpuFullState>`. `GpuFullState`
    drží `CellsGpu`, `BrainGpu`, `HebbianGpu`, `BrownianGpu`, plus
    `rewards_scratch` Vec.
  - CLI flag `--gpu-full` (implies `--gpu`) v `main()`. Init: vytvoří shared
    `GpuContext`, alokuje `CellsGpu` s capacity = `max(initial, max_pop, 64)`,
    upload all initial brains + xoshiro seeds.
  - `run_brain_act` dispatch: gpu_full → `brain_act_gpu_full` (CPU sensor
    gather + populate_inputs jako Sprint 44 path, pak `forward_persistent`,
    download hidden + outputs, CPU motor).
  - `apply_brownian` dispatch: gpu_full → `apply_brownian_gpu` (upload velocities,
    `compute_persistent`, download new velocities). NE-deterministic vs CPU
    Brownian (different PRNG); deterministic across GPU runs (xoshiro seed).
  - `eat_food` modifikováno: pokud gpu_full, sbírá `rewards Vec[N]` (1.0 pro
    cells co snědly), po loop dispatch GPU Hebbian (ne CPU `brain.hebbian_update`).
  - `spawn_children_from_matings` modifikováno: před crossover downloaduje
    parent brain weights z GPU (canonical po GPU Hebbian). Po extend cells
    uploaduje child brain + xoshiro seed na nový slot.
  - `die_and_drop_carrion` modifikováno: gpu_full uses **swap_remove pattern**
    (místo `cells.retain`) → per death `gpu.cells.swap_to(dead_slot, last_slot)`
    GPU-side memcpy přes staging temps. O(deaths) GPU operations, žádný CPU
    transfer.

  *Body 4 — wgpu validation fixes:*
  - wgpu nepovoluje `copy_buffer_to_buffer` se same source + dest buffer →
    `swap_to` routuje přes 2 staging temp buffers (`swap_brain_temp`,
    `swap_xoshiro_temp`).
  - `max_storage_buffers_per_shader_stage = 12` (z Sprint 50) zachováno;
    Brownian používá 2 storage, Hebbian 5, BrainGpu/CellsGpu persistent path 4.
  - Limit nemusí stačit pro plný GPU tick pipeline (Sprint 52+); Sprint 51 ne
    bumpuje dál protože každý subsystém běží jako samostatný dispatch (žádné
    fused 12+ buffer shadery).

- **Konstanty:** žádné nové simulační. SplitMix64 magic numbers v xoshiro
  seeding (`0x9E3779B97F4A7C15`, `0xBF58476D1CE4E5B9`, `0x94D049BB133111EB`)
  jsou standard SplitMix64 reference.

- **Výstup:**
  - `shaders/brownian.wgsl`, `shaders/hebbian.wgsl`: nové compute shadery.

    - `pub struct CellsGpu` + 13 metod (accessors, uploads, downloads, swap_to,

    - `pub struct BrownianGpu` + impl s `compute` (standalone) + `compute_persistent`.

- **Poznámky:**
  - **Hlavní perf win:** brain forward už nepřemístuje 30 MB brain weights
    na GPU každý tick (Sprint 44 limit). Místo toho persistent buffer mutated
    pouze v reproduce (1 brain × ~5 matings/tick = ~15 KB/tick) a die
    (GPU-side memcpy) a Hebbian (in-place na GPU). Při N=10k odhad ~95%
    snížení per-tick PCIe bandwidth pro brain phase.
  - **GPU Hebbian je canonical po --gpu-full.** CPU `cell.genome.brain` je
    stale po eat_food (Hebbian běží jen na GPU). Reproduce phase syncuje
    parent brains z GPU před crossover (per-mating download, ~6 KB) — child

  - **Brownian determinismus:** xoshiro128++ je deterministic per state seed.

    initial state → bit-identical výstup napříč runy. NE deterministic vs

  - **swap_remove vs retain:** `--gpu-full` mode mění `die_and_drop_carrion`

    statisticky equivalent.

    - GPU mating / reproduce kernels (currently CPU pro RNG-heavy crossover).

## Sprint 52 — GPU jako default v rendereru

- **Cíl:** Bevy renderer (`bioscape` binary) konzumuje stejný GPU compute
  pipeline jako headless `--gpu-full`, ale **bez CLI flagu** — GPU compute je
  default chování. Cargo `default = ["gpu"]` zapne feature pro všechny
  binárky; renderer resources init při `setup()`, graceful CPU fallback
  pokud `GpuContext::new` selže.

  **Plán implementace:**

  *Body 1 — feature flag default:*
  - `Cargo.toml` `[features] default = ["gpu"]`. `cargo run --bin bioscape`
    + `cargo run --bin headless` automatycky kompilují wgpu/bytemuck/
    pollster + GPU code path. `cargo build --no-default-features` zachovává
    štíhlý build bez GPU stack.

  *Body 2 — Bevy resources:*
  - `#[cfg(feature = "gpu")] #[derive(Resource)] struct GpuBrainState`
    drží `CellsGpu`, `BrainGpu`, `HebbianGpu`, `BrownianGpu`. Sdílený
    `GpuContext` se po inicializaci zahodí (subsystémy si Arc'd handles
    naklonují).
  - `#[derive(Resource, Default)] struct CellSlotMap` — slot allocator s
    `slot_to_entity: Vec<Entity>` (dense, žádné holes díky swap_remove
    pattern) + `entity_to_slot: HashMap<Entity, usize>`. Methods `allocate(entity)`,
    `release(entity) -> Option<(slot, moved_entity)>`, `slot_of(entity)`.

  *Body 3 — `setup()` GPU init:*
  - Po spawnu INITIAL_CELLS entit a alokaci slotů: pokus o `GpuContext::new()`.
    Při successu vytvoří CellsGpu s `cap = MAX_POPULATION + 64` (slack pro
    ticks kdy Dying entities slot ještě nedrží), upload all initial brains
    + xoshiro seeds (lineage_id ⊕ slot magic), inicializuje BrainGpu /
    HebbianGpu / BrownianGpu, vloží Resource. Při fail logne warn a Resource
    se ne-vloží → systems checkují `Option<Res<GpuBrainState>>` a fallback
    na CPU.

  *Body 4 — refaktor Bevy systems (5×):*
  - `cells_brain_act`: extracted `gather` closure pro sensor + populate_inputs;
    GPU větev: build `inputs_by_slot[N×36]` z entity → slot lookup, upload,
    `forward_persistent`, download hidden + outputs, motor po slot lookup.
    CPU fallback path nezměněn.
  - `apply_brownian_motion`: GPU větev uploaduje velocities by slot,
    `compute_persistent`, downloaduje. CPU fallback uses `cell.apply_brownian`.
  - `cell_eats_food`: collect rewards Vec[N] indexed by slot, na konci
    dispatch `gpu.hebbian.compute_persistent`. Při GPU módu skipne CPU
    `brain.hebbian_update`.
  - `cell_reproduces_on_threshold`: před crossover downloaduje parent brains
    z GPU (`download_brain_at(slot)`), aktualizuje `cell.genome.brain` ze
    GPU canonical state. Po spawn: alokuje slot pro každé child, uploaduje
    child brain + xoshiro seed na nový slot.
  - `cell_dies_on_zero_energy`: po insert `Dying` component release slot z
    `slot_map` (swap_remove pattern). Pokud slot != last, GPU swap_to
    (memcpy přes staging temps) drží sloty dense. Entity zůstane existovat
    pro fade animaci, ale ze sim systems je vyloučená přes `Without<Dying>`.

- **Konstanty:** žádné nové; capacity v setup je `MAX_POPULATION + 64`.

- **Výstup:**
  - `Cargo.toml`: `default = ["gpu"]`.
  - `src/main.rs`:
    - 5 Bevy systems refactored s `Option<Res<GpuBrainState>>` + GPU/CPU
      dispatch.
    - `GpuBrainState` Resource, `CellSlotMap` Resource s dense slot allocator.
    - `setup()` init (init cells + slot map + GPU subsystems with graceful
      fallback).
    - Imports rozšířené o `BRAIN_INPUTS`, `THERMAL_NOISE` + cfg-gated GPU
      types.
  - **73/73 testů pass** (žádné nové unit testy — renderer je integration-only,
    headless `--gpu-full` Sprint 51 testy stále drží jako reference).
  - **Renderer smoke (5 sec launch):** `bevy_render::renderer: AdapterInfo
    { name: "NVIDIA GeForce GTX 1650", backend: Vulkan }` →
    `bioscape: renderer-gpu: persistent brain weights + GPU Hebbian + GPU
    Brownian (cap 1064)`. Sim běží, žádný panic ani crash.

- **Poznámky:**
  - **Žádný CLI flag.** GPU je default chování rendereru. Pokud `GpuContext::new`
    selže (např. ne-Vulkan/Metal/DX12 prostředí), Resource se ne-vloží a
    všechny GPU větve gracefully fallbacknou na CPU bez warn-spam.
  - **Sloty jsou dense.** `swap_remove` pattern v cell_dies_on_zero_energy +
    GPU `swap_to(dst, src)` GPU-side memcpy zaručí, že 0..n je validní range
    pro GPU dispatchy. Sprint 51 headless používá stejný pattern.
  - **CPU brain stale po Hebbian:** GPU Hebbian je canonical po Sprint 51 +
    52. CPU `cell.genome.brain` je out-of-sync; reproduce explicitně syncuje
    parent brains z GPU před crossover (per-mating download, ~3 KB/parent).
  - **Headless behavior nezměněno.** `cargo run --bin headless` bez flagů
    používá CPU rayon path (Sprint 43); `--gpu` brain-only persistent přes
    Sprint 44 path; `--gpu-full` plný persistent přes Sprint 51 path.
    Renderer naopak vždy zkouší GPU.
  - **Sprint 52 totál LOC delta:** ~250 LOC main.rs (resources, slot allocator,
    refactor systems) + 1 LOC Cargo.toml.

- **Decade closure:** Sprinty 43–52 dodávají kompletní GPU compute pipeline
  pro evoluční simulaci. Headless má 3 perf modes (CPU rayon / GPU brain-only
  / GPU full), renderer používá GPU jako default. 12 GPU compute shaderů
  pokrývá brain forward, Hebbian, Brownian (xoshiro RNG), spatial hash
  (counting sort), field diffusion (atomic float CAS), stats reduction,
  cell neighbors query, motor / step / collision / predate / sensor gather.
  Total **~7000 LOC nového kódu napříč 10 sprintů, 73/73 testů, 0 perf
  regressions** (CPU baseline z Sprintu 43 stále drží 1138 ticks/s při
  default size; GPU brain win 3× při N=2000).
